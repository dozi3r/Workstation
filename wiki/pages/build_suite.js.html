Summary: BUILD SUITE - Centralized Asset Compiler, Zero-CORS Bundler & Agent Navigation Engine Authority: ADR-0001, ADR-0002, docs/navigation_manifest.json Functions:

Architectural Role & Subsystem Context

build_suite.js is the Centralized Asset Compiler, Zero-CORS Bundler & Agent Navigation Engine within Volume III: Build Pipeline, Compiler & Legacy Scratch Tooling. Created under 📄 .scratch/creator-remediation/issues/04-build-centralized-compiler.md to eliminate the Multiple Source of Truth Hazard identified in 📄 docs/audit/2026-10-creator-studio-audit-dossier.md and governed by 📄 docs/adr/0001-dual-mode-preset-architecture.md, 📄 docs/adr/0002-dual-srd-and-tiered-module-architecture.md, and 📄 docs/navigation_manifest.json, it is the single build orchestrator that compiles modular HTML/JS sources, multi-campaign sourcebooks, Tarot decks, unified ticket trackers, Compass Headers, and the Bidirectional Codebase Wiki into 100% offline file:/// distributions.

For a deep cross-cutting analysis of this subsystem, consult 🧭 Series E: Zero-CORS Offline Bundling, Compass Headers & Self-Updating Wiki Architecture.

Core Invariants & Contracts

  • Zero External Dependencies: Uses only built-in Node.js standard library modules (fs, path, child_process.execSync) so it can execute on any standalone Node binary discovered by 📄 Build-Suite.ps1.
  • Idempotent Fenced Injection: Every dataset injected into HTML distributions (CAMPAIGN_REGISTRY, MODULES_MANIFEST, DEFAULT_WAVES, ALL_MODULES, TICKETS, MASTER_TICKETS_DATA) is wrapped in deterministic comment fences (// [AUTO-GENERATED ... VIA build_suite.js]) or resolved from 📄 src/workstation/template.html (// @@INJECT_*@@), guaranteeing repeatable builds without file corruption.
  • Script-Safe HTML Serialization: When inlining raw Markdown module bodies or ticket manifests into tags via .replace(/<\/script>/gi, '<\\/script>') and avoids regex $ dollar sign replacement hazards using functional replacers () => replacement.
  • Build-Time Mirror Note (🎫 SYS-AUDIT-01): Lines 487–494 write an identical mirror of 📄 network/platform_audit_dashboard.html to 📄 tickets/creative/platform_audit_visualizer.html, tracked under Category A of 🧭 Series G: Repository Hygiene Audit: Build-Time Mirrors, Legacy Scratch & Orphan Remediation.

AI Agent Maintenance Checklist

  • When adding a new script to src/workstation/scripts/: Add the // @@INCLUDE: scripts/.js @@ directive in 📄 src/workstation/template.html and run 📄 Build-Suite.ps1.
  • When adding a new campaign package under campaigns//: Ensure campaign.json, preset.json, and modules_manifest.json pass 📄 campaigns/Test-CampaignPackage.ps1; build_suite.js Stage 3 will automatically discover and bundle the new campaign on the next build.
  • When modifying AGENTS.md Ground Rules: Edit the template string in Stage 2 of build_suite.js (lines 52–90) rather than editing AGENTS.md directly.

Portable file_url Convention (Tech Debt Wave 0, 2026-10-20)

  • Module file_url values are root-relative (campaigns//modules/.md, URI-encoded per segment) via toRootRelUrl(). No absolute file:///C:/Users/... paths are emitted.
  • Root surfaces (📄 start.html) use them as-is. Subfolder surfaces (📄 network/platform_audit_dashboard.html, 📄 network/network_builder.html, 📄 network/network_visualizer.html) get a ../ prefix at injection time via rebaseFileUrls(json, '../').
  • 📄 network/modules_manifest.json stores root-relative paths (resolve against the repo root, not network/).
  • Injection replacers use functional form () => block so $ sequences in module markdown cannot corrupt output.
