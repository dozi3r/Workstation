🧭 Series E: Zero-CORS Offline Bundling, Compass Headers & Self-Updating Wiki Architecture

Cross-Cutting Subsystem Series Volume III ↓ Jump to Backlinks (12)
🤖 Analytical Knife Seam Summary

How build_suite.js and wiki/build_wiki.js enforce zero-CORS file:/// execution, inline fenced datasets, stamp Compass Headers, and maintain bidirectional backlinks.

IMPORTANT: Cross-Cutting Analytical Series: How 📄 Build-Suite.ps1, 📄 build_suite.js, 📄 wiki/build_wiki.js, and 📄 docs/navigation_manifest.json collaborate to enforce zero-CORS file:/// execution, inline fenced datasets, resolve @@INCLUDE@@ directives, stamp Compass Headers, generate 📄 AGENTS.md, and maintain SHA-256 staleness tracking across the Bidirectional Codebase Wiki.

1. Architectural Seam Overview & Core Problem Statement

Modern browser security engines treat every local file opened over the file:/// protocol as an opaque origin (Origin: null). Consequently, any runtime attempt by an offline HTML application to load external JSON manifests, Markdown modules, or modular JavaScript components via fetch(), XMLHttpRequest, or ES6 tags inside raw module Markdown are escaped as <\/script> to prevent premature script tag termination in the browser DOM.

4. Agent Routing: navigation_manifest.json, AGENTS.md, and Compass Headers

Creator Studio enforces architectural governance across both human contributors and AI coding agents through a three-part routing loop anchored by 📄 docs/navigation_manifest.json:

  • Declarative Authority Registry (docs/navigation_manifest.json): Every user-facing HTML surface, PowerShell runner, and catalog README is registered as an entry in surfaces[] with five mandatory properties: file, type (html, powershell, or markdown), title, authoritative_specs[], data_sources[], and immutable_rule.
  • Root Operating Manual (AGENTS.md): In Stage 2, 📄 build_suite.js overwrites 📄 AGENTS.md at the workspace root with the 5 Ground Rules and the Surface-to-Authority Routing Matrix table compiled directly from navManifest.surfaces. Because 📄 AGENTS.md is auto-generated, manual edits to 📄 AGENTS.md will be overwritten on the next build; permanent routing changes must be made in 📄 docs/navigation_manifest.json.
  • Post-Build Compass Header Stamping (injectCompassHeaders()): In Stage 8, 📄 build_suite.js iterates over every surface in navManifest.surfaces (skipping wiki/index.html, which is generated in Stage 9) and injects or refreshes a standardized CREATOR STUDIO COMPASS HEADER block at line 1 of the file ( for HTML files, <# ... #> for PowerShell scripts). This guarantees that even if an AI agent views a compiled surface file directly without reading 📄 AGENTS.md first, line 1 of the file immediately alerts the agent to its compiled status, its wiki page path, its governing SRDs, and the Build-Suite.ps1 compilation command.

5. Self-Updating Codebase Wiki & SHA-256 Staleness Architecture (wiki/build_wiki.js)

Stage 9 of 📄 build_suite.js invokes 📄 wiki/build_wiki.js to compile the 8-Volume Technical Manual & Bidirectional Codebase Wiki.

5.1 Workspace Discovery & Volume Classification

📄 wiki/build_wiki.js recursively walks the workspace (excluding .git, node_modules, .zip, .pdf, regions/images/, wiki/pages/, and wiki/src/) and classifies every tracked file into one of 8 Volumes (classifyVolume(relPath)) and a specific File Kind (classifyFileKind(relPath)).

5.2 Non-Destructive Custom Notes & SHA-256 Hash Tracking

For every tracked file , 📄 wiki/build_wiki.js maintains a 1:1 Markdown source file at wiki/src/files/.md:

  • Content Hash Computation: computeFileHash(fullPath) computes the first 16 hexadecimal characters of the file's SHA-256 digest (crypto.createHash('sha256').update(buf).digest('hex').slice(0, 16)).
  • Custom Notes Preservation: syncMarkdownSourceForFile(meta) extracts everything inside the ... markers from the existing wiki/src/files/.md file and preserves it untouched while refreshing the YAML frontmatter (current_hash, size_bytes, line_count).
  • Staleness Detection (stale: true | false): The YAML frontmatter stores both current_hash (the live SHA-256 prefix of the source file on disk) and reviewed_hash (the hash when a human or agent last audited the wiki page). If reviewed_hash !== current_hash, isStale is set to true (unless --stamp-reviewed is passed to build_wiki.js), flagging the file in the compiled HTML wiki as needing documentation review.

5.3 Multi-Pass AST Extraction & Bidirectional Knowledge Graph

📄 wiki/build_wiki.js combines static analysis with explicit wiki tokens to construct a complete directed graph (outbound and inbound maps in buildKnowledgeGraph(allMetas)):

  • Static Code & Frontmatter Extraction:
  • .js files: Extracts top JSDoc comments, function signatures (function name(...)), and top-level globals (let/const/var). Cross-references function invocations across src/workstation/scripts/*.js and mods/.
  • .ps1 files: Extracts .SYNOPSIS, .DESCRIPTION, and PowerShell function declarations.
